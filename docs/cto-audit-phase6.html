B What this product is (ELI5) the basics
If you just walked in the door, start here. No jargon.
  1. FACTS = "Fun AI Coding Tools." It's a static code analyzer: it reads code without running it and produces structured facts about it.
  2. One pass, four outputs. A single analyze run emits agent.json (for AI), human.json (for a dashboard), agent.pack (a compressed wire format), and MEMORY.md (a 2–10KB brief).
  3. The problem it solves. AI coding agents waste tokens re-reading whole repos. FACTS gives them a pre-digested map so they read the map, not the territory.
  4. "Card catalog" mental model. Like a library catalog: instead of skimming every book, you look up the card. Cheaper and faster.
  5. Five surfaces, one brain. A CLI, an MCP server, a browser dashboard (ui-remix), a bundled CLI dashboard, and a VS Code extension all share the same analysis engine.
  6. Isomorphic core. The same analysis code runs in Node, in a browser tab, and against an in-memory filesystem — no duplicate logic.
  7. Offline by design. The analyze pass makes zero network calls; anything that touches the network (vuln scan, freshness, telemetry) is a separate, opt-in step.
  8. Deterministic. Same input → byte-identical output (no Date.now()/Math.random() in core), so diffs are meaningful.
  9. Schema-versioned. Artifacts carry FACTS_SCHEMA_VERSION = 0.1.0 and evolve additively (new optional fields only) within a major version.
  10. Two reader audiences. agent.json is exhaustive and machine-shaped; human.json is a CXO-readable summary (one-liner, intent, health).
  11. Phase 6 in one line. This release teaches FACTS to install itself into agents, keep its catalog fresh on every change, and add a real dashboard with security, freshness, and "open in editor."
  12. Token economics is the pitch. The product literally quantifies how many tokens (≈ dollars) the pack saves vs. raw file reads — that's the ROI panel on the dashboard.
C Architecture & the monorepo how it's wired
A pnpm + Turborepo monorepo. Tiers are strictly separated: pure logic can't import Node APIs; only one package may.
  1. Layered tiers. spec (contracts) → core/extractors/scanners/factspack (pure logic) → fs-node/emit/emit-browser (I/O) → cli/mcp-server/ui-remix (surfaces).
  2. Spec is the hub. Every other package depends on @factstack/spec for Zod schemas + TypeScript types; nothing depends back into surfaces.
  3. Dependency injection at the I/O boundary. Core takes a FactsFS interface, never node:fs — that's what makes it isomorphic.
  4. Single Node-import package. Only @factstack/fs-node may import node:*; an eslint "boundaries" rule enforces it.
  5. Three filesystem implementations. fs-node (disk), fs-browser (File System Access API), fs-memory (tests) all satisfy one interface.
  6. Three writer implementations. NodeFileWriter, FsaFileWriter, MemoryFileWriter satisfy one FileWriter interface (writeText/listKeys/removeEntry).
  7. Schemas double as validators. Zod gives runtime validation and static types via z.infer — one source of truth, no drift.
  8. Surfaces can't diverge. CLI and MCP both call executeQuery() from core, so factstack query and the MCP tool always agree.
  9. Apps: apps/cli, apps/mcp-server, apps/ui-remix (+ a browser extension & VS Code extension per project docs).
  10. Packages: spec, core, extractors, scanners, factspack, fs-node, fs-browser, fs-memory, emit, emit-browser, skills, ui-theme.
  11. Tooling is fragile in this environment. pnpm and Turborepo both fail here; work proceeds via npx tsc/vite/tsx/vitest directly (packages resolve to src via the exports map).
  12. No-build dev loop. Because exports map to src, tsx runs the CLI straight from TypeScript with no compile step — fast iteration.
  13. Constraint "C1" is a stated rule. Pure packages declare narrow ambient types (e.g. fetch, AbortSignal) instead of pulling in @types/node or DOM libs.
  14. Wire format is first-class. @factstack/factspack encodes tabular data ~80% smaller than JSON — a real differentiator for MCP bandwidth.
  15. Versioned producer string. Artifacts/packs stamp a producer like factstack/0.3.10 so consumers can detect the generator version.
  16. ES2022 is the type floor. tsconfig.base.json pins lib:["ES2022"] and engines.node >=20.10.0 — important, and a place automated tooling can trip (see §T).

ELI5: the brain. It walks the files, calls all the little readers, builds the dependency map, and writes the catalog.

  3. index.ts is 1139 LOC. The single biggest brain file; future maintenance risk until the orchestrator is decomposed.
  4. diagram.ts (442): three Mermaid views — package topology, hub+importers, focal BFS — each with hard node/edge budgets so output never explodes.
  5. memory.ts (286): generates the MEMORY.md brief, size-bounded <10KB, omits empty sections, deterministic.
  6. docs.ts (276): flags doc files and parses markdown structure once (headings/checkboxes/TODOs/diagrams/links), capped at 96K/file.
  7. review.ts (272): pure buildChangeVerdict() → severity + findings + blast radius, plus a PR-comment markdown renderer.
  8. query.ts (179): the graph query engine; BFS for imports uses a prebuilt adjacency map (was O(depth·V·E), now O(E_frontier)/level).
  9. since.ts (246): two delta strategies — fast mtime path vs. accurate baseline path; diff.ts (143): file-level artifact diff.
  10. learnings.ts (226): append-only JSONL of AI proposals + outcomes — substrate for a future "trust/calibration" feature.
  11. Clever Astro handling. It slices the --- frontmatter, parses it as TS, then re-offsets line numbers so the UI deep-links land on the user's real lines.
  12. Lazy aggregation. env-vars/frameworks/TODOs are collected per-file then aggregated once at the end — amortized cost.
  13. Content budgets everywhere (2.5M total doc chars, 96K/file, top-N truncation) keep artifact JSON bounded.
  14. TODO "blame" is stubbed (authoredAt:null) until git-blame lands — agents can't yet tell old vs. fresh TODOs.
  15. Large-repo memory. One run holds 20+ data structures in locals; a 50k-file monorepo risks memory bloat — no streaming/chunking yet.
  16. One-liner synthesis is regex-careful (won't treat "e.g." / "v0.2" / "Mr." as sentence ends) before falling back to package.json description.
  17. Health headline aggregates broken files (unresolved imports + parse errors), stale files (>6mo + TODO), TODO count, secret count.
  18. Determinism enforced by sort-at-end so byte-identical input yields byte-identical artifacts (critical for the diff feature).
  19. Two delta strategies in since.ts: fast mtime path (changed files only) vs. accurate baseline path (needs a prior artifact).
  20. PR-ready output: renderVerdictMarkdown() turns a change verdict into an emoji + findings-table comment.
  21. Learnings schema is rich (agent/model/action/outcome/confidence/tags/meta) — a real foundation for a trust framework.
  22. Reading-time formula is a stub (LOC/50 + cyclomatic·2/100) and degrades to pure-LOC while complexity is 0.
  23. Monorepo detection is a heuristic (pnpm-workspace/turbo/nx/lerna files) — simple and effective.
  24. Env-var "primary access pattern" scoring marks a dominant style at ≥75%, else "mixed" (null) — nuanced, not naive.
F Package: @factstack/extractors — the readers AST + regex
ELI5: the little specialists. Each one reads code and pulls out one kind of fact — imports, symbols, routes, env-vars.
  1. Shared Babel parse (parse.ts): one AST per file, passed to every extractor via an optional parsed arg — avoids triple-parsing.
  2. djb2 hash cache: fast non-crypto digest keys the per-session parse cache (collisions don't matter for one project's file set).
  3. imports.ts: static/type/dynamic import() + CommonJS require(); imports-python.ts: regex two-pass for from X import Y et al.
  4. symbols.ts (319): functions/classes/interfaces/types/enums/consts; detects React components (PascalCase + JSX) and hooks (use*).
  5. routes.ts: file-based (Next/Remix/Astro) + source-based (Express/FastAPI/Flask/Django) route detection with method extraction.
  6. config-schema.ts: env-var reads (process.env, import.meta.env, os.getenv) with default-value capture; symbols-refs.ts: call/read/jsx/type-ref usage.
  7. Smart route ordering. Astro is checked before Next pages so it doesn't "steal" src/pages/; source pass overlays method-per-export.
  8. Python string/comment stripping uses a small state machine (triple quotes, escapes) so it won't match imports inside docstrings.
  9. Python is regex-only (tree-sitter planned). Edge cases like imports inside exec("…") or f-strings can slip.
  10. Manual ancestor stack (bounded at 32) for env-var default capture — fragile if nesting exceeds the bound.
  11. Component detection is heuristic (PascalCase + JSX); a PascalCase function without a JSX return could be missed.
  12. Cross-file symbol resolution is phase-2 (planned); today symbol-refs are same-file only.
  13. WeakSet/WeakMap skip-sets prevent double-counting declarations as references — careful, correct bookkeeping.
  14. Multi-line Python defs scanned ~20 lines forward to balance parens so signatures aren't truncated.
  15. VS Code-style outline (outline.ts) returns a hierarchy with methods nested under classes — powers the file explorer.
  16. Dynamic + CommonJS imports are recognized (import(), require()), not just static ESM — important for real codebases.
  17. Default-value capture walks parent AST nodes to grab ?? 'x' / || 'x' on env reads.
  18. Babel plugin set is extension-driven — a misconfig could silently fail to parse a TS/JSX file (no plugin-validity check).
  19. djb2 collisions are tolerated by design — the cache is per-session, single-project, so it's safe.

H Package: @factstack/factspack — the compressor ~80% smaller
ELI5: a zip file for facts. It packs tables of data so AI agents pay ~80% fewer tokens to read them.
  1. Tabular wire format with per-column dictionary interning (uppercase columns get F1,F2,… keys) — repeated values shrink dramatically.
  2. Two-pass encoder: render rows (interning) first, then emit header + dict + tables so the dictionary precedes first use.
  3. Forward-reference decoder: a literal may appear after a row that uses it; one resolution sweep fixes it up at the end.
  4. Incremental packs (+ add / x delete rows) support patching without resending everything.
  5. Minimal escaping — only three reserved bytes (tab/newline/backslash); UTF-8 passes through; hot path skips the scan when none are present.
  6. Null vs. empty are distinct (bare - = null; empty-between-tabs = "") — a subtle correctness win.
  7. Tagged error classes (PackEncodeError/DecodeError/EscapeError) let callers discriminate failure modes via instanceof.
  8. No Zod here on purpose — keeps the browser bundle tiny; validation is implicit in the parser contracts.
  9. Strict grammar, no recovery. An unknown line prefix or an unresolved interned key is a hard error with no partial decode — robust but unforgiving.
  10. Schema redeclaration risk. Re-declaring a table is allowed but must match columns exactly; a divergence throws after partial state.
  11. Spec'd separately in docs/FACTSPACK.md with an 8-line decode preamble agents are taught (FACTSPACK_PROMPT.md).
  12. Well-tested (decode.test.ts and friends) — round-trip and edge cases covered.
  13. Interning is first-byte-uppercase (isInternedColumn) — a simple, readable convention for which columns dictionary-compress.
  14. Exactly six line prefixes (# @ & - + x) — header/meta/dict/row/add/delete; anything else is rejected (no forward-compat buffer).
  15. rowCount auto-computed for baseline packs, forced to 0 for incremental — a clean signal of pack kind.
  16. Header fields can't contain tabs/newlines (producer/schema/snapshotId) — enforced, but no documented length cap.
  17. Escape hot-path skip avoids scanning cells with no reserved bytes — a cheap, common-case win.
I Packages: fs-node & emit / emit-browser — the I/O tier disk + browser
ELI5: the hands. They actually read the disk (or browser folder), mine git history, and write the catalog files.
  1. fs-node is the only Node-touching package. Small surface (NodeFS + git miner) makes browser peers easy.
  2. Git mined in one pass. mineGitStats() runs a single git log --name-only -z and buckets touches → lastModified, churnScore, authorCount, top contributors.
  3. ASCII US (0x1f) field separator instead of | so email addresses can't create false splits — a thoughtful detail.
  4. Graceful git fallback. If the log exceeds a 1 GiB buffer, it falls back to a timestamp-only pass; non-git repos return an empty map.
  5. POSIX-normalized paths everywhere; Windows backslashes converted on read.
  6. Silent git degradation. A git failure returns empty stats; success isn't asserted, so "no history" and "git broke" look the same to callers.
  7. No symlink-loop guard in readDir; a self-referential symlink could recurse.
  8. emit-browser mirrors emit — identical pure encode/decode, diverging only at I/O (FSA) and compression (CompressionStream vs zlib).
  9. Post-write verification (FSA). It re-opens each file to catch three real macOS/Safari failure modes (iCloud no-sync, Chrome sandbox no-op, WebKit 0-byte truncate). Defensive and earned.
  10. BufferSource over string writes to dodge old Safari string-encoding bugs.
  11. Verification adds latency. Every browser write does ~4 FSA ops with no batching — slow for snapshot pruning.
  12. Snapshot retention prunes oldest ISO-named JSON beyond a cap (default 50) — bounded history.
  13. Small duplication: shouldGzip() is copied browser-side to avoid importing zlib types — 2 lines, acceptable.

P Security model localhost dashboard
ELI5: the dashboard runs on your own machine. The guards make sure a random website (or a tricked browser) can't use it to read your disk or run your editor.
  1. Binds to 127.0.0.1 (loopback only) — not reachable from the network.
  2. Origin allowlist (isOriginAllowed) accepts only 127.0.0.1:port / localhost:port / [::1]:port — blocks cross-site & DNS-rebind.
  3. NEW: explicit Origin: null rejection — opaque origins (file://, sandboxed iframes) are denied before URL parsing.
  4. Path confinement via safeResolveInside — project-file endpoints can't escape the root with ../.
  5. NEW: symlink real-path re-check on /api/browse — path.resolve is lexical, so a symlink could've slipped the blocklist; now it resolves the real path and re-validates.
  6. No shell anywhere. /api/exec and /api/file-history use spawn/execFile with arg-arrays — no command injection surface.
  7. Capped body reader (1MB) bounds POST memory.
  8. Detached editor spawn with stdio:'ignore' + unref() — the dashboard doesn't inherit the editor's lifetime.
  9. Verified live: C:\Windows browse → 403; missing editor → graceful ok:false; repo browse → 200 with 27 entries.
  10. Two independent review passes found no P0 and called the core model sound.
  11. No auth token. Defense rests on loopback + origin; any local process can hit the API while it runs. Acceptable for a dev tool, worth a token if it ever binds wider.
  12. Telemetry privacy is a security property too: paths/content/hostnames are never recorded; only counts/durations/error categories + a UUID.
  13. Analyze stays offline — the most data-sensitive operation makes no network calls at all.
  14. Browse picker walks the whole disk by design; the blocklist is the only guard there — keep that list current as a security control.
