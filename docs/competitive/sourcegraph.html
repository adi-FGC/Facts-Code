3 · Architecture & open-source plumbing

The product is closed (the main monorepo went private during the enterprise pivot), but the code-intelligence plumbing is open and is exactly the part relevant to FACTS:

SCIP Apache-2.0 · Go

SCIP Code Intelligence Protocol — a language-agnostic, Protobuf-based index format (successor to LSIF) that powers Go-to-definition, Find-references, Find-implementations. Ships Go/Rust bindings, generated TS/Haskell, and a scip CLI.

zoekt Apache-2.0 · Go

Fast trigram-based code search engine. Powers exact/regex Code Search at scale. This is search, not a graph DB.

Indexers

One precise indexer per language emits SCIP: scip-typescript (TS/JS), scip-python, scip-java (Java/Scala/Kotlin), scip-clang (C/C++), scip-ruby, scip-dotnet (C#/VB), rust-analyzer (Rust), scip-dart, scip-php.

Storage reality check

Backed by Postgres + zoekt + stored SCIP blobs. The largest “code graph” company does not use a graph database — strong evidence a graph DB is optional for code intelligence.

4 · The SCIP model (the adoptable artifact)

SCIP is the concrete thing FACTS can consume rather than re-implement per language. Conceptually a SCIP index is: Documents (files) → Occurrences (a symbol referenced at a range, with a role: definition/reference) → Symbols (a stable, structured monikered identity) → SymbolInformation (kind, docs, relationships like implementation/type_definition). It’s designed for cross-repo, language-agnostic precise navigation.

scip-typescript index            # emit index.scip for a TS/JS repo
scip print index.scip            # inspect occurrences / symbols
# → ingest occurrences+symbols → your own graph (FACTS does this in scip_ingest-style)

5 · Enterprise posture

  • Security/compliance: SOC2 Type II + ISO27001; zero data retention on LLM inference (never stored beyond what’s required, never shared).
  • Scale: built for the world’s largest monorepos and multi-repo architectures; “indexes all of your repositories.”
  • Access: SSO (SAML/OIDC/OAuth), SCIM provisioning, RBAC; dedicated account + support engineers.
  • Proof: a “CodeScaleBench” report claims it makes agents “faster, cheaper, and more accurate.”
