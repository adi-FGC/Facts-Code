1 · What it is & positioning

Graphify is a knowledge-graph builder distributed as an AI-assistant skill. You run /graphify . inside your coding agent and it turns a folder into a graph of entities and relationships, then your agent queries the graph instead of reading raw files. Its differentiator vs. pure code-graph tools is multi-modality: “app code + database schema + infrastructure in one graph,” plus docs, papers, images, and video/audio.

It is the largest and most mature of the three systems (60k+ stars, YC-backed, an accompanying book The Memory Layer, an active commercial entity at graphifylabs.ai). MIT-licensed core, with paid/extra modalities as opt-in installs.

2 · Architecture

A clean functional pipeline; each stage is one module communicating via plain dicts + NetworkX graphs, with no side effects outside graphify-out/.

The three extraction passes

Pass 1 — Code

Tree-sitter AST, fully local, no API calls. ~25–28 grammars. Classes, functions, imports, call graphs, inline comments. SQL gets special treatment: tables, views, foreign keys, JOIN relationships. A code-only corpus skips Pass 3 entirely & needs no API key.

Pass 2 — Video/Audio

Transcribed locally with faster-whisper. The transcription prompt is seeded with the top god-nodes from the code graph so transcripts focus on your domain. Cached across re-runs.

Pass 3 — Docs/Papers/Images

Claude (or other backend) subagents run in parallel over markdown/PDF/image/transcripts; each emits a JSON fragment of nodes/edges; fragments merge into one graph. This is the only pass that costs tokens.

Graph format

NetworkX node-link graph.json. Node: id, label, file_type, source_file. Edge: source, target, relation, confidence, confidence_score, source_file. Hyperedges (3+ nodes) live in G.graph["hyperedges"].

3 · Signature features

  • Confidence / provenance tagging on every edge — EXTRACTED (1.0), INFERRED (discrete rubric 0.55–0.95 with a confidence_score), AMBIGUOUS (flagged for human review). You always know what was found vs. guessed.
  • Leiden community detection — modules discovered by edge density. No embeddings / no vector DB: the graph structure (incl. semantically_similar_to edges) is the similarity signal.
  • God nodes (most-connected concepts), surprising connections (cross-module links ranked by unexpectedness), suggested questions (4–5 the graph is uniquely positioned to answer).
  • The “why” — # NOTE: / # WHY: / # HACK: comments, docstrings, and design rationale become first-class nodes linked to the code they explain.
  • Multi-modal corpus — code, SQL, Terraform/HCL, MCP configs, docs (md/mdx/rst/html/yaml), Office (docx/xlsx), Google Workspace, PDF, images, video/audio, and YouTube/URLs via graphify add <url>.
  • PR intelligence — graphify prs (CI/review/worktree state), prs 42 (graph impact of a PR), prs --triage (AI-ranked review queue), prs --conflicts (PRs sharing graph communities = merge-order risk).

4 · Interface & commands

/graphify .                       # build graph for current folder
/graphify ./docs --update         # re-extract only changed files
/graphify . --cluster-only        # rerun clustering without re-extracting
/graphify . --wiki                # agent-crawlable markdown wiki
graphify export callflow-html     # Mermaid call-flow HTML

/graphify query "what connects auth to the database?"
/graphify path "UserService" "DatabasePool"
/graphify explain "RateLimiter"
/graphify add https://arxiv.org/abs/1706.03762   # fetch + add a paper

graphify hook install             # auto-rebuild on git commit (AST only, free)
graphify merge-graphs a.json b.json
graphify prs --triage             # AI ranks your review queue

MCP server (python -m graphify.serve graph.json) exposes: query_graph, get_node, get_neighbors, shortest_path, list_prs, get_pr_impact, triage_prs.

Querying is natural-language → subgraph, not fixed verbs: it returns a minimal relevant slice of the graph.

5 · Distribution & adoption model

  • Skill into ~20 assistants: Claude Code, Codex, OpenCode, Kilo, Cursor, Gemini CLI, Copilot (CLI + VS Code), Aider, Amp, OpenClaw, Factory Droid, Trae, Hermes, Kimi, Kiro, Pi, Devin, Google Antigravity. graphify install [--project] [--platform X].
  • One-line install: uv tool install graphifyy / pipx install graphifyy (both manage PATH); optional extras [pdf] [office] [video] [mcp] [neo4j] [sql] [terraform] [all].
  • Always-on “query-first” nudging: persistent instruction files (AGENTS.md, .cursor/rules/*.mdc alwaysApply, CLAUDE.md) plus payload-bearing hooks (Claude Code, Gemini, Kilo plugin) that fire before search/Read/Glob tool calls and push the agent toward graphify query rather than grepping.
  • Pluggable backends: Claude, Gemini, OpenAI, DeepSeek, Kimi/Moonshot, Ollama (fully local), AWS Bedrock (IAM, no key).

6 · Team / VCS workflow

  • graphify-out/ is meant to be committed — one person builds, everyone pulls the map; their assistant reads it immediately.
  • Git post-commit hook auto-rebuilds (AST only, no API cost) and installs a git merge driver so graph.json is union-merged — never left with conflict markers.
  • Portable manifest.json (relative paths, re-anchored on load) so committing avoids a full rebuild on first checkout.
  • .graphifyignore (gitignore syntax + ! negation); respects .gitignore automatically.

7 · Performance & scale

Ghost-dup mergeAST-vs-semantic duplicates auto-merged at build time (dedup.py/semantic_cleanup.py)

Token benchmark: on a mixed corpus (Karpathy repos + 5 papers + 4 images, 52 files) graphify reports 71.5× fewer tokens per query vs reading raw files; savings scale with corpus size (≈1× at 6 files — there the value is structural clarity, not compression). Runnable worked/ folders ship the raw inputs + actual outputs to reproduce.

8 · Security & privacy

  • Dedicated security module + documented threat model (SECURITY.md): validate_url() (http/https only, blocks file:// redirects), safe_fetch() (size cap + timeout), validate_graph_path() (must resolve inside graphify-out/), sanitize_label() (strip control chars, cap 256, HTML-escape).
  • Local by default: code via tree-sitter and audio via faster-whisper never leave the machine; only docs/PDF/image semantic extraction hits a model API. No telemetry.
  • Query logging (local JSONL at ~/.cache/graphify-queries.log; responses off by default; opt-out env vars).

↳ Relevance to FACTS / FactsPack

Graphify is the “graph-intelligence & reach” benchmark. The pieces most worth borrowing into FACTS:

  • Confidence tagging (EXTRACTED/INFERRED/AMBIGUOUS) — cheap, and perfectly aligned with FACTS’s deterministic/inspectable ethos. Add a confidence column to FactsPack edge tables.
  • Leiden clustering + god-nodes + surprising connections + the “why” — turns FACTS’s dependency graph into insight, and feeds the CXO dashboard real material.
  • NL query → minimal subgraph — graduate FACTS beyond fixed verbs (callers/imports/cycles/orphans), returning a FactsPack-encoded slice.
  • Skill + one-line installer + always-on query-first hooks — the adoption engine FACTS lacks (it is MCP-config-only today).
  • Committable graph + merge driver + post-commit hook — make .facts/ a team artifact, not a per-machine cache.
  • Reproducible, runnable benchmarks — FACTS has spec-level token tables; graphify ships worked/ folders. Credibility.
  • Multi-modality & SQL/IaC extraction — the “whole-stack in one graph” story; tree-sitter or SCIP ingest to escape JS/TS-only.

Where FACTS still differentiates: the FactsPack wire format (graphify ships full graph.json, no token-optimized transport), a human/CXO editorial dashboard, and built-in secrets detection.
