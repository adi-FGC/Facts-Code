Neo4j substrate · role & lessons

A graph database — the property-graph storage + query + algorithms engine. Unlike the other four, it is not a code-intelligence tool; it’s the layer a code-intelligence tool could store its graph in. The useful question isn’t “FACTS vs Neo4j” but “what does FACTS borrow from it, and should it ever depend on it?”

1 · Where Neo4j fits in this picture

Every system here builds a graph of the codebase; they differ in where that graph lives. Neo4j is one option for the persistence/query tier — the heavyweight, graph-native one:

So Neo4j’s place is the opt-in “power-user / enterprise graph” backend & export target — reach for it when the graph is large, traversals are deep, and you want a declarative query language plus a graph-algorithms catalog. Graphify already supports it; Sourcegraph proves you can run planet-scale code intelligence without it.

2 · What it does that’s worth studying

Labeled property graph

Nodes and relationships both carry typed properties; relationships are first-class and directed with a type. Maps cleanly to code: (:Symbol), (:File), [:CALLS], [:IMPORTS], [:DEFINED_IN], each with properties.

Cypher query language

Declarative pattern matching with variable-length paths — the thing SQL is bad at:

MATCH (a:Function {name:'login'})
      -[:CALLS*1..3]->(b:Function)
RETURN b

“All functions reachable within 3 calls of login” in one line.

Graph Data Science (GDS)

A catalog of production graph algorithms: PageRank & centrality (importance), Louvain/Leiden community detection (modules), shortest-path, cycle detection, node similarity, weakly/strongly connected components.

GraphRAG + vector index

Neo4j 5.x added native vector indexes; its flagship pattern is GraphRAG — seed with vector/keyword hits, then expand along relationships to assemble a connected context subgraph for the LLM. Graph-aware retrieval, not flat top-k.

3 · The lessons for FACTS (adopt concepts, not the server)

Neo4j ideaWhat FACTS should take from it
Property-graph schemaFormalize FACTS’s model as typed nodes + typed, directed, property-bearing edges with labels. It maps 1:1 to FactsPack tables and makes export (Neo4j/GraphML) trivial.
Cypher variable-length pathsFACTS’s fixed verbs (callers/imports/cycles/orphans) are hardcoded special cases of pattern matching. Ship a tiny Cypher-subset that compiles to SQLite recursive CTEs — arbitrary structural queries, no new database.
PageRank / centralityRank “key files / god nodes” by PageRank over the import/call graph, not raw in-degree (what MEMORY.md uses today). Importance ≠ popularity.
Louvain / LeidenCluster the codebase into modules/communities for the brief and the CXO dashboard (this is exactly what Graphify does). Reference algorithms live in GDS.
MERGE semanticsModel incremental refresh as idempotent upsert-by-stable-id of nodes/edges — the clean fix for ghost-duplicates and partial re-index.
GraphRAG retrievalMake FACTS’s pre-injection layer graph-aware: start from entities named in the prompt, expand along edges (callees/callers/imports) to a connected subgraph, emit it as FactsPack. Don’t rank files independently.
Bloom visualizationInform the dashboard’s interactive graph exploration (the human/Insights surface).

⚠ Where NOT to follow Neo4j

Do not make a Neo4j server a hard dependency or the default store. It needs a running database, isn’t git-committable, and adds ops weight — which would break FACTS’s core moat: local, zero-infra, deterministic, commit-the-graph. Sourcegraph (Postgres) and FACTS (SQLite) both show graph-native storage is optional for code intelligence. Keep SQLite + FactsPack as the substrate.

↳ Net recommendation

Steal the model and the math, skip the server. Adopt the property-graph schema, a Cypher-subset compiled to SQLite CTEs, GDS-style algorithms (PageRank for importance, Leiden for modules), MERGE-style incremental updates, and the GraphRAG retrieval pattern. Then offer Neo4j only as an optional export — facts export --neo4j / GraphML — for teams who already run it and want Cypher/Bloom/GDS on the FACTS graph. That mirrors Graphify’s [neo4j] extra without taking on the dependency.
