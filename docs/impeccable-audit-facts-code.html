Anti-patterns verdict

PASS · distinctive, intentional

Does this look AI-generated? No. Real type system (Inter + JetBrains Mono via a shared theme package), a full CSS-custom-property token model with genuine dark/light, an editorial layout language, and in-house renderers instead of component-library defaults. None of the cardinal tells are present: no gradient text, no hero-metric template, no default glassmorphism, no purple-on-white. Executive summary

Health: 17/20 (Good). The dashboard's standout strengths are its theming (a real token system, lightningcss in the pipeline) and its anti-pattern discipline (distinctive, not slop). The weakest dimensions are performance (a 96 KB-gz first-paint bundle that ships every tab's body because routes aren't code-split) and responsive depth on the data-dense tables. Accessibility is good but uneven across the newest, hand-built surfaces.

  • [P1] Routes are not code-split — every tab's body sits in the main bundle (~96 KB gz), flagged repeatedly in the bundle-budget history. Lazy-load route bodies.
  • [P2] The new CSS-suggestions drawer + docs sub-views lack the a11y polish of the older tabs — focus management on open, ARIA on the collapsible handle, and a roving-tabindex doc list.
  • [P2] Data-dense tables (Files, Library, Vulnerabilities) have no mobile reflow — they scroll horizontally below ~600px rather than restructuring.
  • [P3] Side-stripe accent borders appear on several cards/callouts — swap for full borders, tint, or a leading marker.
  • [P3] Hand-rolled Markdown renderer escapes inline edge cases narrowly — fine for project docs, worth hardening if it ever renders untrusted content.

The directional pass guessed data tables overflow on mobile. They don't. At 375px the Overview reflows cleanly and the Files view has zero horizontal overflow (widest element = the 375px viewport; no <table> element at all). Checkpoint 202 was wrong and has been downgraded.

Systemic & positive

Patterns worth naming

Systemic · first-paint weight

All routes live in the entry chunk. The fix is structural (route-level code-splitting), not per-component — it would claw first paint from ~96 KB toward ~55 KB.

Systemic · newest surfaces lag on a11y

The Docs tab + CSS drawer were built fast this cycle; they trail the older tabs on focus management and dynamic announcements. One a11y pass would close the gap.

Systemic · side-stripe reflex

The border-left:3px accent recurs across callouts and panel cards. It reads as a single habit, not many mistakes — a token-level fix.

Positive · token discipline

Colors, spacing, and type all flow from CSS custom properties. Theme switching is data-attribute driven and complete. This is the strongest dimension.

Positive · no library bloat

Markdown and diagrams are rendered in-house rather than pulling marked/mermaid. The whole CSS-audit + Docs feature cost ~0.8 KB gz.

Positive · keyboard-first scaffolding

Skip link, programmatic <main> focus target, command palette (⌘K), and segmented tablists with proper roles are already in place.
