FACTS — design & animations

How FACTS looks, feels, and moves. The visual language, motion vocabulary, and the engineering judgment baked into both. Written for whoever is shaping the next surface or polishing an existing one.

Spec sources design_spec.md, animations_spec.md Tokens packages/ui-theme/src/tokens.css Companion handoff.html Status not deployed — open locally

1 · Design principles

  1. Evidence-first — every chip, badge, and claim is clickable and resolves to its source. No unfalsifiable "health: good."
  2. Progressive depth — the CXO lands on one screen that tells the story; the developer drills as deep as they need. The UI reveals complexity only on demand.
  3. Quiet by default — no marketing gradients, no dense dashboards on first paint. Space and typography carry the weight before color does.
  4. Dark is first-class — not "dark mode as an afterthought." The dark palette was designed from the graph canvas outwards, not color-inverted from light.
  5. Liquid-glass aesthetic — modern, translucent surfaces that feel contemporary on 2026-era hardware without sliding into skeuomorphism. §2.
  6. Fluid across scales — 340 px on a budget Android to 8K on a creative-director's reference monitor, the layout always makes sense.

2 · Liquid-glass aesthetic

Translucent chrome surfaces only — top nav, LHS panel, RHS local-tab bar, mobile drawer, tooltips, ⌘K palette, context menus. The "liquid glass" is what frames content; the content itself stays solid. 

backdrop-filter: blur(18px);
background: rgba(var(--surface-rgb), 0.48);  /* dark */
background: rgba(var(--surface-rgb), 0.62);  /* light */
box-shadow:
  inset 0 0 0 1px rgba(255, 255, 255, 0.14),   /* glass meniscus */
  0 6px 16px rgba(0, 0, 0, 0.18);              /* lift shadow */
contain: paint;                                 /* perf hygiene */

On hover, a 300 ms linear-gradient sweeps across the surface — a specular highlight that signals interactivity without resorting to color change. See §12.

Where glass is NOT applied

Content areas, code previews, the graph canvas, anywhere legibility matters more than aesthetic. Glass is chrome, not content.

Fallback: @supports not (backdrop-filter: blur(1px)) → solid translucent background, no blur. No layout shift; no reduced function.

Performance: contain: paint on all glass surfaces. Mobile (< 900 px) drops blur to solid on devices flagged via UA hints or prefers-reduced-transparency.

Principles

  • clamp() all widths — no stepped transitions.
  • Container queries for component-level responsiveness. A tree node renders the same in the LHS (narrow) or in a ⌘K result row (medium).
  • Never stretch edge-to-edge on 4K/8K. Line lengths stay readable; extra width becomes breathing room.
  • Viewport units: dvw, dvh, svh where they shine (true dynamic viewports on mobile); Lightning CSS polyfills older Safari / tablet split-view cases.

5.2 Light vs dark — not inverted

Dark is tuned independently, not color-inverted from light:

  • --bg dark: #0B0D10 (near-black with a cool tint).
  • --surface-1 dark: #14171C.
  • --fg dark: #E6E8EA (softened off-white to reduce fatigue).
  • Accent stays the brand hue in both modes but desaturated ~15% in dark.
  • WCAG AA minimum on text against any surface; AAA on body text.

5.3 Semantic colors

  • --ok — successful save, healthy check, granted permission.
  • --warn — optional/advisory state (e.g., persistent storage not granted but app still works).
  • --danger — failing check, error banner, destructive action.
  • --info — neutral informational. Used sparingly; the accent often serves the same role.

7 · Layout patterns

  • Grid + 1fr columns with min-width: 0 on the body cell. The min-width: 0 is load-bearing — without it, a wide SVG inside makes the grid track grow past the viewport, causing the page to scroll horizontally instead of the figure box.
  • Containers own their scroll axes. Wide artifacts (DAG, sequence diagram, code preview) use overflow: auto + max-width: 100% so the page never has to scroll horizontally.
  • Sticky chrome, scrollable content. Top nav, LHS tree, and the modal scrim are sticky/fixed; everything inside scrolls independently.
  • Asymmetric layouts. Don't center everything — left-aligned bodies with the lede 64ch wide and the meta block left-flush read as designed, not templated.

8 · Component patterns

  • Hairlines, not heavy borders. 1px solid var(--hairline) at ~8% opacity. The shape comes from typography + spacing, not chrome.
  • Accent left rules on callouts (2 px solid accent + dashed hairline on the other three sides). Editorial, not card-like.
  • Cards only when grouping is real. Don't wrap every block in a card. Whitespace + a hairline does more work for less noise.
  • Never nest cards. If you find yourself doing it, hierarchy is wrong.
  • Tabs underline, don't pill. Active state is a 2 px accent rule under the label, no background fill.
  • Mono for chrome, body for content. Tab labels, status pills, kickers, code = mono. Lede, body text, headlines = sans.
  • Icons only when load-bearing. The default is no icon. Add one when it carries info the label can't (e.g., status dot).

9 · Motion principles

  1. Motion serves comprehension, not decoration. A file-select transition keeps the tree node visually linked to the RHS preview — object permanence across the navigation, what builds trust for non-developer viewers.
  2. Default durations: ≤ 300 ms for common actions; 500 ms ceiling for signature moments.
  3. prefers-reduced-motion: reduce disables all non-essential motion — instant state swaps. No startViewTransition calls. No specular sweeps. No blur animations. Verified in CI.
  4. Never block input for more than one frame.
  5. Named transitions are per-element, unique per DOM, and cleaned up on unmount.

Suspense-aware: Remix v3's streaming + viewTransition can land a transition on a loading skeleton, then re-animate to real content (jarring). The waitForSuspense() wrapper defers the transition until the next paint after suspense resolves. Used by Files tab, Graph tab, History tab.

Fallback: "startViewTransition" in document feature-detect. On unsupported browsers (older Safari, Firefox < 129): navigations are instant — no layout shift, no broken visuals. The Playwright test matrix exercises both paths.

12 · Inline motion catalog

Hover & focus

  • Specular sweep on glass — 300 ms linear-gradient translate across the surface. Signals interactivity without color change. Glass only.
  • Color shift — color 120 ms var(--ease-out-quart). Used on row hover (muted → fg) and link hover.
  • Lean-in — 3 px padding-left shift on row hover. Tiny, but signals interactivity at the row level. Used in recents list, file tree, env-check rows.
  • Focus rings — :focus-visible with 2 px solid var(--accent) outline + -2 px outline-offset. Visible on keyboard nav, suppressed on mouse click.

Page-load stagger

  • Recents list rows enter staggered, 30 ms apart, capped at 8 rows (rows 9+ enter together so a 12-row list doesn't have a 360 ms tail).
  • OpenModal overlay fades in over 140 ms; panel slides up 6 px over 220 ms with both fill so the final state survives the keyframe end.

Status feedback

  • Save success: green dot + savedNote, no animation beyond the panel fade. The signal is the dot, not motion.
  • Re-analyze complete: status bar pulses (450 ms), changed tree rows flash with a subtle background fade.

13 · Reduced motion handling

@media (prefers-reduced-motion: reduce) {
  html { scroll-behavior: auto; }
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}

Plus: no startViewTransition calls — feature-detect matchMedia('(prefers-reduced-motion: reduce)').matches and fall through to the synchronous commit path. No specular sweeps. No blur animations.

Verified in CI: the Playwright matrix runs with reduced-motion on/off to make sure both paths produce the same final visual state.

14 · Performance budgets

  • First paint: Main JS ≤ 72 KB gz (current cap; bump requires a justification comment in check-bundle-size.mjs).
  • Lazy JS: ≤ 200 KB gz (worker + dynamic imports — paid only when the user clicks Open).
  • CSS: ≤ 8 KB gz total.
  • Frame budget: 16 ms (60 fps). Glass blurs use contain: paint. Hover animations are transform/opacity only (compositor-only, no layout).
  • Animation properties: transform + opacity only. Never animate width/height/top/left/padding/margin — they trigger layout.

15 · Anti-patterns ("AI slop" detector)

If the UI starts looking like generic 2024-era AI output, you're probably doing one of these:

Don't Cyan-on-dark + purple-to-blue gradients. The default AI palette. Replace with the tuned-for-dark accent.
Do Single accent hue, desaturated ~15% in dark, neutrals tinted toward brand.
Don't Glassmorphism on content. Glass is chrome only.
Do Solid surfaces for content; reserve blur for nav, modals, tooltips, palette.
Don't Hero metric layout — big number, small label, supporting stats, gradient accent. Done to death.
Do Treat stats as evidence: clickable, resolves to source. Quiet typography, no decoration.
Don't Cards inside cards inside cards. Visual noise.
Do Flatten. Whitespace + hairlines beat nested chrome.
Don't Bounce or elastic easing on UI. Reads as tacky.
Do Out-quart / out-expo curves. Real objects decelerate smoothly.
Don't Gray text on colored backgrounds. Washed out.
Do Tint the muted text toward the background hue (color-mix with bg).
Don't Rounded rectangles with generic drop shadows. Could be any AI output.
Do Hairline borders + editorial accent rules. Memorable shape comes from restraint.
The AI Slop Test

If someone said "AI made this," would they believe it immediately? If yes, that's the problem. A distinctive interface makes someone ask "how was this made?" — not "which AI made this?"

16 · New-component checklist

When you're shaping a new surface, walk this list before declaring done:

  1. Tokens only. No hex, no px outside the 4 pt grid, no inline font sizes outside the scale.
  2. Dark + light both check out. Toggle and look. WCAG AA on text.
  3. 340 px and 1920 px both work. Container queries, not media queries, where possible.
  4. Keyboard nav lands somewhere visible. Tab through it. :focus-visible must show a 2 px accent ring.
  5. Reduced motion produces a sensible final state. Set prefers-reduced-motion: reduce in DevTools and verify.
  6. No nested cards. No gradient text. No rounded-rect-with-shadow drop-in. Re-read §15.
  7. Glass only on chrome. If you're tempted to put it on content, you want a hairline instead.
  8. Hover state exists and is purposeful. Specular sweep on glass, color shift elsewhere, no decoration-only animations.
  9. Bundle size measured. Run pnpm -F @factstack/ui-remix build — caps must hold.
  10. Evidence-first. Every claim resolves to source. Health badges click through. Status pills explain themselves.
