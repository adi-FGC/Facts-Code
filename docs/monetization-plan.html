Factsv1 — Monetization & Roadmap

Fast AI Coding Tools · local-first, cloud-supercharged · for first-time programmers, experienced engineers, and CTOs

The goal: a valuable coding tool that is local-first but gains superpowers in the cloud — priced so the cloud tier is easy to charge for yet more than worth it. The name is the promise: Fast AI Coding Tools.

§Summary — the monetization thesis

Factsv1's free/paid line is drawn by physics, not preference: anything that runs on one machine, one repo, deterministically is the free acquisition engine (zero infra cost, proves value, works offline, commits to git). Anything that needs shared, hosted, historical, or cross-repo state is a cloud superpower that captures willingness-to-pay. The strategy in five moves:

1 · Free local engine = acquisition + proof

The local product (accurate code graph, ask-your-codebase queries, auto-context for your agent on a single repo, token-savings counter, one-command install) must be the best free code-context tool. It proves the value before any charge — the freemium prerequisite.

2 · Cloud amplifies, never unlocks, the core

We never paywall the core loop (single-repo context — the literal "fast AI coding" benefit). We charge for its cloud amplification: cross-repo, team-shared, always-fresh, and historical. Local stays honest; cloud stays compelling.

3 · "More than worth it" is provable, not asserted

Token accounting (F7) + the ROI harness (F13) turn the pitch into a number: cheaper, fewer-turn agent runs. If a seat saves more in tokens + engineer hours than it costs, the sale closes itself.

4 · CTO value beyond coding speed

Graph analytics (F5) — hotspots, knowledge-risk/bus-factor, blast-radius, portfolio health — gives leaders a reason to buy that engineers' tools never reach. This is the high-WTP wedge and the expansion path.

Three personas, three doors, one funnel: first-time programmers enter free (the "how to read this codebase" brief, the "why" rationale, plain-English queries) → experienced engineers stay for free local power and convert to Pro cloud → CTOs buy Team/Enterprise for analytics, ROI, and governance. Each door widens the one above it.

1Sequenced path to the goal

Three phases. Each is independently shippable and each must precede the next for a reason that is both technical (features depend on earlier ones) and commercial (you can't sell a cloud tier before a free base is adopted and proven).

MVP  The free local engine — acquire & prove value

Goal: one command, point at a repo, and get a symbol-accurate graph, plain-English answers with citations, a "fast AI coding" context boost on that repo, and a visible token-savings number — all offline, committable, free.

Monetization role: pure acquisition. No charge yet — this is the value proof and the install surface where the cloud upsell will later be introduced.

↓
Why MVP precedes V1. Technically: V1's headline — auto-assembled context (F4) and analytics (F5) — are built on top of the MVP's graph (F2), retrieval (F3), and token budgeting (F7); they cannot exist first. Commercially: a cloud tier has nothing to amplify and nobody to convert until the free local tool is adopted and has already proven token savings. You earn the right to charge by giving value first.

V1  Cloud superpowers — capture willingness-to-pay

Goal: turn the proven free engine into a team/cloud product. The agent gets always-fresh, cross-repo, team-shared context; leaders get analytics and ROI. This is the first real revenue.

Monetization role: the core paid tier (Pro + Team). F4-cloud and F5 are the superpowers; F13 + F7 prove they pay for themselves; F6 widens the addressable market.

↓
Why V1 precedes Later. Technically: enterprise breadth (whole-stack graph, export) extends the mature symbol graph, analytics, and multi-language base that V1 establishes. Commercially: governance and org-wide standardization only become buying criteria after teams are already paying for V1 and want to roll it out company-wide. You move up-market from product-market fit, not before it.

Later  Enterprise & breadth — expand ACV & defensibility

Goal: become the org-wide standard — span app + data + infrastructure, integrate with enterprise tooling, and satisfy procurement.

F11 Whole-stack (SQL/IaC/docs) F14 Graph export + governance: SSO/SCIM/RBAC, on-prem/VPC, audit, portfolio health, SLA

Monetization role: Enterprise tier & expansion revenue — higher ACV, multi-year, defensible.

2Weighted feature list

Every feature scored 1–5 on four dimensions, combined into a weighted composite, ranked high-to-low. Weights reflect the brief: it asks for a valuable tool that we can charge well for, so impact and monetization dominate; demand validates the funnel; build ease is a sequencing tiebreaker, weighted lowest because a high-value feature is worth building even when it's hard.

Dimensions & weights

  • Impact on core goal — 35%. Does it advance "fast AI coding, local-first + cloud superpower"?
  • Monetization potential — 30%. Can it capture willingness-to-pay / be cleanly gated?
  • User demand — 20%. How loudly the market asks for it (validated by the landscape scan).
  • Build ease — 15%. Scored as ease, not effort: 5 = quick win, 1 = heavy lift — so low effort contributes positively.

Composite formula

composite = 0.35 · Impact + 0.30 · Monetization + 0.20 · Demand + 0.15 · Ease (every term 1–5 → composite 1.0–5.0)

Ease maps from build size: S→5, S/M→4, M→3, M/L→2, L→1.

3Free vs. paid breakdown

Freemium logic applied: free features drive acquisition and prove value (and cost us no infra because they're local); paid features capture willingness-to-pay from power users and teams — gating scale, sharing, history, and analytics rather than core utility, so the free tier is never crippled.

F4 · Graph-aware context (the crown jewel) Freemium → Paid Free: single-repo, local pre-injected context (the core loop). Paid: cross-repo, team-shared, always-fresh remote context API. This is "fast AI coding" — blocking it would betray local-first. Free proves it on your repo; the cloud version (the part that's genuinely impossible locally at scale) captures the WTP.
F5 · Graph analytics (hotspots / impact) Paid (Team) + free teaser Free: one-shot impact / blast-radius query. Paid: historical hotspots, knowledge-risk/bus-factor, portfolio dashboards. The single impact query is engineer utility (acquisition); the historical, exec-facing analytics are the CTO's reason to buy — highest WTP, cleanly gated behind hosted history.
F2 · Symbol-level graph Free → Paid @ scale Free: single-repo graph (up to a repo-size / symbol cap). Paid: cross-repo & very-large-monorepo cloud indexing. The graph is core utility and must prove value free; cross-repo indexing is infra-heavy and only possible in the cloud — natural paid line.
F12 · Distribution (skill / installer) Free Always free. It's the install surface where the cloud upsell is introduced. The acquisition engine. Gating install would kill the funnel — the opposite of freemium intent.
F7 · Live token accounting Free → Paid ROI Free: local token counter + per-session savings. Paid: aggregated org/team ROI dashboards + history. Savings must be free to prove — it's the value evidence. The org-level ROI rollup (a buyer artifact) is paid.
F3 · Declarative + NL query Freemium Free: structured queries + basic NL up to a daily cap. Paid: unlimited + hosted/team-shared NL endpoint. "Ask your codebase" is the acquisition magic, so it must be tasted free; heavy/hosted volume is where cost and value concentrate → cap it.
F6 · Multi-language extraction Free core → Paid long-tail Free: top languages. Paid: exotic/enterprise languages + cloud bulk indexing. Breadth grows the funnel, so popular languages stay free; the long tail and cloud-accelerated indexing are upsells.
F9 · Session / cross-session memory Freemium Free: personal local memory. Paid: team-shared / org context store. Personal continuity is a free retention hook; sharing memory across a team is a collaboration feature → paid.
F11 · Whole-stack (SQL / IaC / docs) Paid (Team/Ent) Free: docs-as-nodes linking. Paid: SQL schema + IaC graph & governance. App+data+infra in one graph is an enterprise differentiator with clear WTP; the lightweight docs-linking stays free as a teaser.
F8 · Incremental + git hook Free Always free locally. (Cloud CI-scale refresh is part of Team infra, not a gate on the local hook.) "Fast" is in the name — slow local refresh would cripple core utility. Table-stakes stay free.
F13 · Benchmark / ROI harness Free CLI → Paid hosted Free: local benchmark CLI. Paid: hosted ROI/benchmark reporting for buyers. A free CLI lets champions prove value bottoms-up (drives adoption + expansion); the polished buyer-facing report is a sales asset → paid.
F1 · Provenance & confidence Free Always free. A trust label that costs nothing to give and builds the credibility that underpins every paid claim. Gating it would erode trust.
F10 · Rationale ("the why") Free Always free. High onboarding value for first-time programmers and cheap to build — pure top-of-funnel acquisition.
F14 · Graph export Paid (Pro/Ent) Free: basic GraphML. Paid: enterprise DB / tooling connectors. A power-user/enterprise integration with low broad demand — reasonable to keep behind Pro+ without affecting core utility.
The one guardrail that ties it together: the free tier always contains a complete, useful local loop — graph + query + single-repo context + token proof + install — so a solo user never hits a wall on core utility. Everything paid is an amplifier (scale, sharing, history, analytics, ROI), which is exactly where CTOs and teams have budget and where the cloud is genuinely better than local. That is how we "charge well" without ever making the tool feel crippled — and why the charge is "more than worth it."
