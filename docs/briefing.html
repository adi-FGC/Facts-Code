Executive Briefing · deep edition·FACTS — Fun AI Coding Tools·~20 min read

Understand a codebase once. Serve that understanding to people and AI at the same time.

In the AI-coding era, the most expensive step in software is no longer writing code — it's understanding the code that already exists, repeatedly, for every person and every agent who touches it. FACTS does that work one time and turns it into a shared, structured asset: a dashboard a stakeholder can read, and a compact fact-pack an AI agent can act on. This is the long-form briefing a sponsor or an incoming CTO needs — the case, the engineering, and the full picture.

1 pass → 2 audiences 19 packages · 158 source files 45 test suites ~80% cheaper AI context 0 network calls by default v0.1 · alpha · dogfoods itself

If you read one thing

  • WhatA cross-platform static code analyzer. Point it at any repository; it produces one structured, evidence-first picture of that codebase.
  • WedgeIt serves both readers from a single pass — a human dashboard and an AI-agent fact-pack that cannot drift from each other, because they're cut from the same analysis.
  • Why nowAI coding agents are powerful but blind and expensive — they re-read the whole repo every session. FACTS makes "understanding the code" a reusable asset and cuts the cost of feeding an agent by roughly 5×.
  • EdgeIt also measures whether your AI agents can be trusted — an append-only ledger records every proposal and outcome, so agent accuracy becomes a number, not a hope.
  • StateWorking analyzer, CLI, AI-tool server, and dashboard. Early (v0.1, alpha). Safe by design: your code never leaves the machine during a normal run.
Part I

The case

Why this exists, what it puts in your hands, and what it saves — the part a sponsor needs to decide whether to care.

01 · The thesis

The bottleneck moved from writing code to understanding it.

what a person gets what an AI agent gets

For decades, the scarce resource in software was the time to write code. AI assistants have largely removed that constraint. The new bottleneck is comprehension: an agent that can write a function in seconds still has to re-learn your entire system before it can safely change anything — and it does that, from scratch, in every session. Meanwhile the humans who fund and govern that system — executives, auditors, new engineers — have no current, trustworthy map of it at all.

Both sides are paying, repeatedly, for the same missing thing: a faithful, up-to-date understanding of the codebase. FACTS's bet is that this understanding should be produced once and reused, like a build artifact — not re-derived by every reader, human or machine.

One analysis pass produces two artifacts: a path-addressable map for AI agents, and a CXO-readable dashboard for anyone who can't read the source. Same truth, different shape — they can't drift, because they're the same pass.

02 · What it produces

Two deliverables, plus the connective tissue.

Everything below falls out of a single run. One is shaped for human eyes; one for an AI's token budget.

for people · the dashboard

A skimmable executive view

What a sponsor, auditor, or new hire needs in ten seconds — no developer walkthrough required.

  • One-line intent — what this system is, in a sentence
  • Health headline — broken / stale / secrets / TODOs at a glance
  • Stack & size — languages, lines, and AI token cost
  • Activity & ownership — what's changing, and who touches it
  • Every number links to the file it came from — evidence-first
for agents · the fact-pack

A dense, actionable map

What an AI needs to change the code safely — without re-reading every file.

  • Per-file outline — symbols, imports, exports, complexity
  • Dependency graph — what depends on what, and blast radius
  • Risks — leaked secrets, known CVEs, license & structural issues
  • A "read-me-first" brief (MEMORY.md) for instant cold-starts
  • Auto-generated agent config for Claude, Cursor & Copilot

03 · The economics

AI context is a recurring cost. FACTS cuts it ~5×.

Every time an AI agent "reads your repo," you pay for it in tokens — the unit AI models bill by. A large codebase can cost tens of thousands of tokens to load cold, and agents do it again and again. As AI usage scales across your engineering org, this becomes a real, recurring line item — and a latency tax, because an agent that reads less responds faster.

The mechanism: FACTS emits a purpose-built wire format (FactsPack) that names each long value once and refers to it by a short id thereafter — and ships only the changes on each refresh. On representative payloads that is ~80–90% fewer tokens than the equivalent JSON, losslessly.

Conventional JSON — ~150 tokens[
  {"id":1,"kind":"fn","name":"login","file":"src/auth.ts","line":42},
  {"id":2,"kind":"fn","name":"logout","file":"src/auth.ts","line":58},
  {"id":3,"kind":"cls","name":"User","file":"src/auth.ts","line":10}
]
FactsPack — ~60 tokens@ F1=src/auth.ts
& symbols  id  k    n       F   l
- 1        fn   login   F1  42
- 2        fn   logout  F1  58
- 3        cls  User    F1  10
≈ 60–90% fewer tokens · same data · then only deltas on refresh

Compounding effect: across a long agent session the cost model flips from "re-send the whole repo every turn" to "one full read, then kilobyte-sized deltas." The MEMORY.md brief sharpens the same lever — an agent gets oriented from a 2–10 KB file instead of a 40–200 KB cold read.

Why it matters

This is cost avoidance that compounds with adoption. The more your teams lean on AI agents, the more a cheaper, reusable context pays back — in both the model bill and developer wait time.

05 · The pipeline

Six stages, on a tidy belt.

Each stage is its own package; they only hand work forward. Here's what each one actually does.

StagePackageWhat it does
1 · WalkwalkerVisits every file, honoring .gitignore/.dockerignore/.aiignore; skips build output & binaries (null-byte sniff, 1 MB cap).
2 · ParseextractorsReads each file's structure without running it — JS/TS via Babel today; one parse, reused by every consumer.
3 · ExtractextractorsPulls out symbols, imports/exports, routes, and the environment variables the code reads.
4 · GraphgraphResolves imports into a dependency graph; computes callers (blast radius) and detects cycles.
5 · ScanscannersSweeps for leaked secrets, vulnerable dependencies, risky licenses, and stale TODOs.
6 · Summarizeintent · coreInfers the one-line intent and assembles both artifacts, the health headline, and the diagrams.

The discipline underneath: the engine never touches the disk or the network directly — file access is handed in through a small interface (FactsFS), and even compression is injected as a callback. That single rule (the codebase calls it "isomorphic / constraint C1") is what lets the identical analyzer run in your CI pipeline and inside a browser tab via a Web Worker — and it's what keeps the analysis reproducible and testable in memory.

06 · The dependency graph & queries

From "a pile of files" to "a map you can ask questions of."

The graph is where structural truth lives. FACTS resolves every import to a real file — following relative paths, workspace packages (@scope/pkg), and TypeScript path aliases (@lib/*) — while correctly treating Node built-ins and third-party packages as external. An import that should resolve to a project file but doesn't is surfaced as a broken-import risk, not silently dropped.

Blast radius

For any file, how many other modules transitively depend on it. The "if I break this, what else breaks?" number — computed by walking the graph's reverse edges.

Cycles

Strongly-connected components in the import graph — the tangles (A → B → A) that make a codebase hard to change safely. Detected and surfaced as findings.

Orphans

Files nothing imports — candidate dead code, cross-checked so a real entry point isn't mistaken for waste.

One query engine, two front doors: the same four verbs — callers, imports, cycles, orphans — drive both the CLI's query command and the AI server's query_graph tool, so an answer can never differ between a developer and an agent. The graph also renders to Mermaid in three views (package / hub / focal) an agent can read instead of inferring the architecture call-by-call.

Why it matters

Blast radius and cycle detection are exactly what turns "review by reading everything and hoping" into review by grounded risk — and they're the raw inputs to the Change Verdict in Part III.

07 · Security & supply chain

Safe to point at proprietary code — by design.

For a tool that reads your entire source tree, posture is the first question. The guarantees below are structural, not settings you have to remember to flip.

🔒

Your code stays put

A normal analysis makes zero network calls — nothing is uploaded. Dependency CVE checking is a separate, explicit, opt-in step.

🛡️

Secrets can't leak back out

If the scanner finds a credential, it emits only a redacted preview (first4***last2). There is no raw field on the finding type — leak-proof by construction, not by convention.

📦

Supply-chain aware

Detects dependency manifests across npm, PyPI, Cargo, Go, Maven & RubyGems, matches them against OSV.dev advisories (CVE + GHSA), and flags risky licenses.

📐

Reproducible & stable

Same input → same output (test-pinned to be byte-identical), and data contracts are versioned additive-only — no breaking surprises.

How the secret scanner avoids crying wolf

It ships a curated rule set — AWS keys, Google, Stripe, Slack, GitHub, OpenAI, Anthropic tokens, and PEM private-key blocks — but a pattern match alone isn't enough. Each candidate must also clear a Shannon-entropy floor (a measure of randomness): a real AKIA… key looks random; a placeholder like AKIAEXAMPLE does not. That second gate is what keeps the Credentials list signal, not noise.

On the supply-chain query: OSV.dev is free and needs no auth, and its batch endpoint takes up to 1000 package queries in a single round-trip — a whole repo's dependency set checked in one request, with a pluggable cache. Today npm manifests are fully parsed; PyPI / Cargo / Go / Maven / RubyGems are detected (full dependency parsing is on the roadmap), surfaced honestly rather than skipped in silence.

Why it matters

These are exactly the questions a security or compliance review asks. The answer to "does our code leave the building?" is no — and "could this tool itself leak a secret it found?" is structurally no.

08 · Memory & calibration

The part that governs your AI agents.

Two systems most analyzers don't have — one makes agents cheap to start, the other makes them accountable.

cold-start · MEMORY.md

The "read me first" brief

A compact, deterministic 2–10 KB markdown digest an agent reads before doing anything.

  • Replaces a 40–200 KB cold read of the full artifact
  • Ordered, size-bounded sections — the structure is part of the contract
  • Byte-identical for identical input — pure, no clock, no randomness
  • The MCP server tells agents to call it first
accountability · learnings.jsonl

A trust ledger for AI

An append-only log of every AI proposal and what happened to it.

  • Records {agent, action, outcome, confidence} per proposal
  • Answers "this agent is right 84% of the time on refactors" — with evidence
  • Git-diffable audit trail — grep who proposed what, and when
  • FACTS logs its own runs too, as a self-calibrating time series

Why JSONL: one self-contained event per line means appends are O(1), a corrupt line can't break the rest of the file, and tail -f … | jq works as a live console. It's the substrate for a planned "trust framework" — deciding how much autonomy to grant an agent based on its measured track record in your repo.

Why it matters

As you delegate more to AI, "should we trust it to merge?" stops being a vibe and becomes a metric. This is AI governance you can audit — and it's already wired into every analysis run.

10 · The flagship feature

The Change Verdict — PR risk in one line.

This is the differentiator currently being built, and it ties the whole engine together. Instead of a wall of metrics, FACTS gives every code change one opinionated answer: how risky is this, and exactly why. A reviewer — human or AI — reads a single headline instead of re-deriving the diff.

How it decides: it compares the before and after of an analysis and fuses the deltas — new secrets, new known-vulnerabilities, new structural cycles — with blast radius (how many other modules transitively depend on what changed). The worst finding sets the severity.

none low medium high critical
High risk Introduces 1 new secret; touches a hub 22 modules depend on. (+3 ~5 files)
Introduces 1 new secret — a leaked credential appeared in this change. Rotate before merge.
Introduces 1 new dependency cycle — a new structural loop, e.g. a → b → a.
Touches a hub — a changed file is imported by 22 modules; a bug here has wide reach.
Why it matters

It moves review from "read everything and hope" to "triage by grounded risk." The same verdict posts to a pull request and is callable by an AI reviewer — so faster and safer stop being a trade-off. The scoring lives in one shared place, so all three surfaces agree by construction.

14 · Glossary

The terms, in plain words.

Everything a non-engineer needs to read the rest of this briefing — and the dashboard — without a translator.

Token
The unit an AI model reads and bills by — very roughly ¾ of a word. "Context cost" is measured in tokens.
Artifact
A file FACTS produces from one analysis (e.g. agent.json, human.json) — a reusable output, like a build artifact.
Dependency graph
A map of which file imports which. The architecture, drawn from the actual code rather than a diagram someone drew once.
Blast radius
How many other parts of the system depend on a given file — i.e. how much could break if you change it.
Cycle (SCC)
A loop in the graph where files depend on each other (A → B → A). A structural smell that makes change risky.
Isomorphic
The same code runs in two very different places — here, a terminal and a web browser — without modification.
MCP
Model Context Protocol — the standard way an AI assistant (Claude, Cursor) plugs into external "tools." FACTS ships an MCP server.
FactsPack
FACTS's compact text format for handing data to AI agents at ~⅕ the token cost of JSON.
OSV
Open Source Vulnerabilities — a free, public database of known security flaws in software packages. FACTS queries it for CVEs.
CVE / GHSA
Standard identifiers for a publicly known security vulnerability (e.g. CVE-2024-1234).
SBOM
Software Bill of Materials — the "ingredients list" of every dependency in a product. FACTS produces the raw material for one.
Static analysis
Learning about code by reading its structure, without running it. Safe and fast.
Determinism
Same input always yields the exact same output — what makes results trustworthy and diff-able over time.
