Anti-patterns verdict

QUALIFIED PASS · functional, one generic tell

Does this look AI-generated? Mostly no — it reads as a real developer tool, not a template. No gradient text, no hero-metric block, no default glassmorphism, no purple-on-white. Inline lucide-style SVG icons (not emoji-as-iconography), genuine dark mode, dense and information-first. The one tell: it leans on Tailwind's default gray/blue palette with only four custom @theme tokens, which is the single most common "built fast with Tailwind" fingerprint. All-monospace at 13px is distinctive but verges on costume. Net: distinctive enough to pass, one palette-level habit to retire.

Executive summary

Health: 13/20 (Acceptable — significant work on responsive + performance). The viewer is genuinely strong on accessibility scaffolding (three skip links, an aria-live region, focus-visible rings, role="tree"/dialog) and on developer ergonomics (the folder switcher, "Copy for LLM", terminal/editor launch, /-to-search). Its two weakest dimensions are exactly what the project's own 2026 audit flagged: responsive (a single 900px breakpoint that hides the sidebar instead of restructuring) and performance (Tailwind loaded from a CDN at runtime).

  • [P1] Tailwind is loaded from a CDN browser build (unpkg.com/@tailwindcss/browser@4) — runtime compilation, a hard network dependency, FOUC risk, and a broken experience offline or behind a firewall. For a "self-contained HTML viewer", this is the headline issue.
  • [P1] Mobile layout collapses rather than adapts — below 900px the shell drops to one column and hides the tree/resizer; the overloaded header still wraps and steals vertical space (the project's own audit measured a ~1453px shell at 390px wide).
  • [P1] The header is one packed flex row — path bar + change/rescan/copy + meta + 4 view tabs + 3 action buttons + theme + search. Brittle at medium widths.
  • [P2] No real token system — colors are hardcoded Tailwind utilities (gray-50, blue-600) with only 4 @theme entries; theme changes mean find-and-replace, not a variable swap.
  • [P2] The DAG is a canvas with no table/list fallback and partial keyboard support — keyboard + screen-reader users can't reach the graph's value.

A11y 3/4 · verified

Measured live: 3 skip links, 1 role=tree, an aria-live region, header/nav/main landmarks, 27 real buttons, a single h1. (The welcome screen's recent-project rows are cursor:pointer divs, not in the ARIA tree, a verified keyboard/AT gap.)

Perf 2/4 · verified (P1)

The page loads exactly 2 resources, one being unpkg.com/@tailwindcss/browser@4. Tailwind compiles in the browser at runtime; the whole UI hinges on that one CDN fetch.

Responsive 2/4 · verified (P1)

At a 375px viewport the #shell renders 1254px wide and is clipped by overflow:hidden (no reflow); 19 interactive elements measure under 44×44px. The mobile screenshot shows the header + cards cut off at the right edge.

Anti-patterns 3/4 · verified

Emoji in the chrome (🌳 on the welcome screen, ⚠ "30 dirty" in the header) and the stale "Zero dependencies, pure Node.js" footer claim, both visible on render.

Architecture smell · confirmed

Clicking a recent project navigated the browser to GET /api/scan?path=…, a side-effecting GET that scans the filesystem, exactly as the 2026 self-audit warned. Verified by the resulting URL.

Renders clean

Systemic & positive

Patterns worth naming

Systemic · runtime CDN dependency

The viewer's styling, its responsive behaviour, and its offline story all hinge on a CDN Tailwind build compiling in the browser. One change (ship compiled CSS) fixes perf, offline, and FOUC at once.

Systemic · desktop-grid assumptions

Fixed 24dvw columns, calc(100vh - …) heights, and a one-row header assume a wide screen. Mobile is handled by hiding, not restructuring — a shell-layout module is the real fix.

Systemic · hardcoded palette

Tailwind grays/blues are sprinkled across every fragment. Promoting them to @theme tokens would make theming a variable change, not a sweep.

Positive · a11y scaffolding

Three skip links, a polite live region, focus-visible rings, keyboard tree focus, dialog semantics on the folder modal. Real effort, ahead of most generated viewers.

Positive · developer ergonomics

The folder switcher (recent + browse), "Copy for LLM", terminal/editor launch, and /-search make this feel built by someone who uses dev tools daily.

Positive · zero-config instant value

One command, one self-contained HTML file, no build. Time-to-first-value is the thing Facts-Code should study and protect.
