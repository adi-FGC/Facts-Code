# Audit IDs cited in the code

Comments and test names cite review findings by ID (`security#3`, `CLI-13`, `SCN-P2-02`…). The
reports that defined them are local-only (gitignored), so this is where an ID resolves: one line
each, plus the file to read. `test/audit-ids.test.mjs` fails when code cites an ID that has no row
here, so add the row in the same change as the comment. It also fails on an ID-shaped token of a
family it does not know: add the family to its `AUDIT_ID` pattern (and a line below), or list a
non-audit prefix in `NOT_AUDIT`.

## How to read an ID

| Form                                                                        | Source                                                                                                                                                                                                                                                                           |
| --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `category#rank` (`security#3`, `tech-debt#6`)                               | Rank inside one category of a pre-merge audit sweep (correctness, security, performance, data-model, deploy-infra, ux, tech-debt). **Sweeps reuse the numbers**, so one ID can mean different things; each row gives every meaning in use and says which file cites which.       |
| `AREA-NN` (`CLI-13`, `SCN-03`, `MCP-12`, `FSB-11`, `UI-08`, `HUNT-CORE-05`) | A bug-hunt pass over one area: CLI, scanners, MCP server, browser file system, dashboard UI, analyzer core.                                                                                                                                                                      |
| `AREA-Rn`, `AREA-REV-n`, `AREA-P2-NN`, `x-r3-n`, `x-rev-n`, `mcp-r3-adv-n`  | Follow-up rounds on those passes: R = review round, REV / rev = reviewer finding, P2 = second pass, adv = adversarial probe.                                                                                                                                                     |
| `cli-dry-n`, `core-dup-NN`                                                  | Duplication findings (two copies of one rule that could drift).                                                                                                                                                                                                                  |
| `mcp-pkg-n`, `legacy-ui-Rn`                                                 | Reviews of the MCP npm package and of the CLI's legacy UI.                                                                                                                                                                                                                       |
| Short codes (`AE-1`, `DET-2`, `DI-1`, `EH-3`, `OPD-2`, `SEC-1`, `XP-1`…)    | Themed passes: alias edges, determinism, deterministic iteration, error handling, ops/deploy, security, cross-platform, test coverage (`TC`), concurrency (`CONC`), resilience (`RES`), the pack format (`ART`), the import resolver (`CG`), secret scanning and grading (`SV`). |
| `QA ISSUE-n` (`ISSUE-2`)                                                    | A QA pass over the hosted dashboard.                                                                                                                                                                                                                                             |

Not audit IDs: `INV1`–`INV7` are architecture invariants, `ft-1`…`ft-11` are roadmap items
(`docs/roadmap.html`), `F1`…`F18` are feature-plan items (`F8` = the parse cache).
