Capability map

Every feature FACTS has shipped

FACTS — Fun AI Coding Tools — is a cross-platform static code analyzer. One analysis pass over a project directory produces two artifacts: an AgentArtifact (a dense, AI-readable map of the codebase) and a HumanArtifact (CXO-readable dashboard data) — plus a live MCP surface for coding agents. This document maps every shipped feature with its logic (how it works) and its use case (why it exists).

1 · What FACTS is

Most code-intelligence tools answer one audience. FACTS answers three from a single analysis: AI coding agents (who need a dense, token-cheap map to act safely), developers (who need to navigate + understand), and CXOs / leads (who need health + risk at a glance). The core analysis is isomorphic — the same logic runs in a Node CLI, a browser tab (no install), an MCP server, and in-memory tests — because every I/O touchpoint flows through a pluggable interface (see §10).

Reading this doc Each feature is a card: Logic = the mechanism (real functions/files), Use case = the question it answers and who asks it. For how the tiers fit together, see docs/handoff.html; for what's planned, see docs/roadmap.html.

2 · The one-pass pipeline

Every surface composes the same ordered pipeline. Point it at a directory; get two artifacts out.

directory
  → walker  gitignore-aware file discovery (over a FactsFS adapter)
  → parsers  web-tree-sitter WASM grammars per language
  → extractors  AST → FileOutline (imports, exports, declarations, routes, TODOs)
  → graph  resolve imports → dependency graph + cycles
  → scanners  secrets · licenses · frameworks · complexity · token-cost · bundle-size
  → intent  compose a one-sentence "what this project IS"
  → core.analyze()  assembles → AgentArtifact + HumanArtifact
  → emit  writes .facts/{agent.json, human.json, agent.jsonl, agent.pack, MEMORY.md, snapshots/}

The constraint that makes this portable: everything from the walker through core is isomorphic — no node:* imports. Filesystem access is injected via the FactsFS interface; artifact writing via the FileWriter interface. Swap the adapter, run the identical analysis anywhere.

3 · Analysis engine

The isomorphic core that turns source into structured facts.

Gitignore-aware walker@factstack/walker

LogicWalks a directory through the injected FactsFS interface (never node:fs directly), honoring .gitignore + a built-in exclude set (node_modules, dist, .git, build outputs, playwright trace dirs). Emits the candidate file list the rest of the pipeline consumes.

UseThe entry point of every analysis. Keeps the walk identical across Node, browser, and tests because it depends only on the interface, not a concrete filesystem.

WASM grammar registry@factstack/parsers

Logicweb-tree-sitter (WASM) grammar registry — no native bindings, so it runs identically in Node and the browser (constraint C1). Lazy-loads the grammar for each detected language and exposes a uniform parse surface to the extractors.

UseLanguage-agnostic AST access. The reason FACTS can analyze a repo in a browser tab with zero install.

Per-language extractors@factstack/extractors

LogicPure functions take AST nodes in, emit a FileOutline out: imports, exports, declarations (symbols), HTTP routes, framework components, TODO/FIXME markers, and the symbol outline. Framework-aware (Express, Remix, Next, FastAPI, Astro, node-http, etc.) for route detection.

UseTurns "a file" into "what this file declares, imports, and exposes." Feeds the graph, the outline view, and the route map.

Dependency graph + cycle detection@factstack/graph

LogicResolves each extracted import specifier to a concrete file (the resolver handles relative paths, package entries, and subpath aliases), building the canonical graph.edges[] with edge kinds (import / type-import / dynamic-import). Detects cycles and computes in/out degree.

UseAnswers "what imports X / what does X import / where are the cycles." Backs the query verb, the Graph + Flow tabs, and the diagram emitter.

Deterministic intent generator@factstack/intent

LogicComposes signals (frameworks, monorepo shape, sub-apps, routes, capabilities) into a single CXO-readable sentence describing what the project is. Pure: no LLM, no Date, no I/O — byte-identical output for identical input.

UseThe one-line "what am I looking at" for the Overview tab + MEMORY.md. Deterministic so it never drifts between runs or costs a token.

analyze() orchestrator@factstack/core

Logicanalyze(fs, opts) composes walker → parsers → extractors → graph → scanners → intent and assembles the AgentArtifact + HumanArtifact. Isomorphic — never imports a Node built-in; receives a FactsFS + a gzip fn + git stats from the caller.

UseThe single function every surface calls. CLI, MCP server, browser scanner, and tests all run the identical analysis through it.

Reading-time estimator@factstack/core

LogiccomputeReadingTime derives a per-file "minutes to read through" from LOC + complexity, summable across a subset. Stored on each file in the artifact.

Use"How long to understand the minimum viable subset of this repo?" A CXO-facing onboarding-cost signal.

Learnings log + self-calibration@factstack/core

LogicformatLearningEvent / parseLearningsJsonl / queryLearnings / selfCalibrateEvent append + filter proposal/outcome events in .facts/learnings.jsonl (agent, action, outcome ∈ accepted|rejected|pending|self-calibrate). Every analyze appends a self-calibrate row.

UseThe foundation of a trust framework: "what have this codebase's agents been right about?" Calibration data accrues from day one.

5 · Artifacts & emitters

What the analysis writes, and the pure transformers that shape each output.

agent.json + human.json@factstack/emit

LogicwriteArtifactsTo(writer, agent, human, opts) serializes both Zod-validated artifacts through a FileWriter, plus the streamable agent.jsonl and (Node-only) a node:sqlite index. Schemas are the single source of truth in @factstack/spec.

UseThe canonical outputs. agent.json = the AI map; human.json = the dashboard data; jsonl = line-streamable consumption.

MEMORY.md brief@factstack/core · buildMemory

LogicbuildMemory(agent, human) synthesizes a deterministic 2–10 KB markdown digest (intent, stack, key files, routes, top risks) with strict section-omission + caps. Pure markdown emitter.

UseThe brief an AI agent reads FIRST when joining a project — replaces a 40–200 KB cold-read of agent.json with a 10–100× cheaper digest.

FactsPack (.pack) wire format@factstack/factspack

LogicA line-oriented binary/text wire format encoding tabular data (symbols, imports, callers, findings). Pure encode/decode per docs/FACTSPACK.md; ~80% token reduction vs JSON.

UseCheap MCP responses. When an agent asks for callers/imports/findings, the pack format keeps the token bill ~5× lower than JSON. An 8-line decoder preamble teaches any agent to read it.

Snapshots + diff engine@factstack/core · diffArtifacts

LogicEach analyze writes a compact stats snapshot to .facts/snapshots/<ISO>.json. diffArtifacts(from, to) computes deltas: added/removed/changed files, headline stat changes, and a vulnerability ID-set diff with a weighted severity-shift score (critical 4 / high 3 / medium 2 / low 1) so a "+1 critical, −1 low" PR reads +3, not a misleading 0.

Use"What changed since my last session / since the base branch?" Backs the History tab, the diff verb, and the CI risk gate.

humanToViz transformer@factstack/emit

LogichumanToViz(agent, human) reshapes the artifacts into the VizArtifact the web dashboard consumes (tree rollups, language splits, edges, routes). Pure.

UseThe bridge between analysis output and the UI's data shape. Lets the dashboard render without re-deriving anything.

Self-contained HTML export@factstack/emit · CLI export

LogicBakes the viz dataset inline into the dashboard HTML and strips CDN deps, producing a single file that opens via file:// with no server.

UseShare a codebase report as one HTML file — email it, attach it to a PR, open it offline.

6 · AI-agent integration

The tier that turns FACTS analysis into things coding agents + CI actually consume. Shipped across v0.6–v0.7.

Skill / rule auto-generator@factstack/skills · idea #21

LogicOne canonical SkillSpec IR (extracted from agent+human) feeds three per-format renderers: Claude .claude/skills/factstack-<slug>/SKILL.md, Cursor .cursorrules, GitHub Copilot .github/copilot-instructions.md. buildSkillsTo(writer, agent, human, formats?) orchestrates through any FileWriter.

UseEvery coding agent gets project-specific onboarding for free. Run factstack export-skills and the agent that opens the repo already knows the stack, key files, entry points, and open risks.

Mermaid diagram generator@factstack/core · idea #86

LogicbuildDiagram(agent, opts) emits Mermaid flowcharts in three views: package (inter-package edges, aggregated with counts), hub (top-N most-imported files + importers), focal (caller graph BFS rooted on a file). Edge styling encodes kind (--> import, -.-> type, ==> dynamic). Hard node caps keep output renderable.

UseMakes the dependency graph shareable in PR descriptions, READMEs, and docs. A reviewer sees the architecture without opening the dashboard.

PR risk gate (ci-report)apps/cli · idea #45

LogicrenderCiReport(diff, opts) emits a markdown PR comment: headline verdict (verb chosen by severity-shift sign), stats table, new/fixed vuln IDs, optional embedded Mermaid diagram (auto-picked view), collapsed file changes. --fail-on-shift <n> exits non-zero when severity worsens past a threshold.

UseTurns FACTS from "I run it locally" into "every PR is gated." Post the report as a comment; block merges that grow the risk surface.

Mandatory onboarding sequence@factstack/skills

LogicEvery generated skill embeds a fixed MCP tool sequence to run on first contact: read_memory → analyze → query_graph → list_risks → list_credentials → list_vulnerabilities.

UseConverts a passive context dump into an operational checklist — the agent knows exactly how to bootstrap against live data.

10 · The adapter seam

The design decision that makes "run anywhere" real. Two interfaces in @factstack/spec, each with three implementations.

The two seams FactsFS (read) — how the analyzer reads project files. FileWriter (write) — where artifacts land. The walker + analyze() depend only on these interfaces, never on a concrete filesystem, so the same analysis logic runs in three environments by swapping the adapter.
AdapterImplementsUse case
NodeFS / NodeFileWriterFactsFS / FileWriter over node:fsThe CLI + MCP server. Only layer allowed to import node:fs.
FsaBrowserFS / FsaFileWriterFactsFS / FileWriter over the File System Access APIIn-browser scan with no install. Includes macOS silent-write-failure readback defenses.
MemoryFS / MemoryFileWriterFactsFS / FileWriter in memoryTests + fixture-driven CI — microseconds per test, no disk, no permissions.

The skills + emit orchestrators (buildSkillsTo, writeArtifactsTo) take a FileWriter as their first argument precisely so the identical orchestration runs across all three. This is the "one adapter ⇒ hypothetical seam, two adapters ⇒ real seam" principle the codebase follows.

11 · Testing

FACTS dogfoods itself and tests at two levels.

Unit tests (vitest)every package

Logic~700+ vitest tests across packages. Pure functions (buildMemory, diffArtifacts, buildDiagram, extractors, scanners) are tested for determinism + caps + edge cases; orchestrators use the MemoryFileWriter shim.

UseEvery feature in this catalog has unit coverage. Determinism is a hard contract — same input, byte-identical output.

End-to-end suite (Playwright)apps/ui-remix/test/e2e

LogicPer-route smoke (all 13 tabs load, no console errors), Vulnerabilities form interaction, and an interactions spec (command palette, theme/density apply to html[data-*], Flow view modes, Library sort). A waitForReady helper distinguishes the loaded shell from the error screen; an auto-fixture fails any test that logs a console error.

UseCatches "page renders but the control is dead" regressions that unit tests can't see — runs against the built+inlined output, matching production.
