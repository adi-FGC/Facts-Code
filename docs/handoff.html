FACTS — codebase handoff

What this codebase does, why it exists, how it's organized, and where to look first when you pick it up. Written for the AI agent or human contributor inheriting the next chunk of work.

Repo factstack/ Branch apps-remix3 Live demo factstack-demo.netlify.app Companion doc design-handoff.html Status not deployed — open locally

1 · Mission

FACTS produces two artifacts from one analysis pass of any code project:

  1. An AI-agent-optimized codebase map (agent.json, agent.jsonl, agent.pack) so coding agents reason about the repo without re-reading every file.
  2. A CXO-readable executive dashboard (human.json + WebUI) so CTOs, CPOs, investors, and other non-coding stakeholders understand what a codebase does, what it's made of, and where its risks sit — without a developer walking them through it.

One analysis. Two audiences. Same truth.

Read the canonical spec at app_spec.md at the repo root for acceptance criteria; this doc is the navigable summary.

4 · Architecture

4.1 Tier model

Per app_spec.md constraint C1, the analyzer is split into tiers ordered by which Node features they're allowed to use. The constraint is enforced by ESLint boundaries + the package layout:

  1. spec — Zod schemas + abstract interfaces (FactsFS, FileWriter). No I/O of its own. Everything below depends on it; nothing else lives at this tier.
  2. fs-* adapters — fs-node, fs-memory, fs-browser. Each implements FactsFS. Isomorphic constraint: none can import node:* except fs-node.
  3. walker, parsers, extractors, graph, scanners, intent, core — the isomorphic analyzer tier. Pure (input → output). No I/O, no node:*.
  4. emit/pure — isomorphic serialization (encodeAgentPack, humanToViz, writeArtifactsTo orchestrator).
  5. emit (Node-side I/O), emit-browser (FSA-side I/O) — adapters that wrap the orchestrator and provide platform-specific wiring (gitignore for Node, FSA permission upgrade for browser).
  6. apps/* — CLI, MCP server, UI. Compose the analyzer with their respective adapters.

4.2 Read tier — FactsFS

Pure interface for "where files are read from." Defined in packages/spec/src/fs.ts. Methods: readFile, readText, readDir, stat, readlink, normalize, join. Implemented by NodeFS, MemoryFS, FsaBrowserFS.

The walker takes a FactsFS and produces walked files; downstream extractors never know which adapter they're running on. The isomorphic guarantee means the same analyzer ships everywhere — CLI, web worker, Chrome extension future.

4.3 Write tier — FileWriter + orchestrator

Introduced in commit d697226, May 2026. The write tier was forked into two top-level functions (writeArtifacts in emit/, writeBrowserArtifacts in emit-browser/) that duplicated ~200 LOC of orchestration. The deepening introduced a shared orchestrator + adapter interface, mirroring the read-tier FactsFS pattern.

Read CONTEXT.md at the repo root for the canonical vocabulary; the short version:

FileWriter Pure interface for "where artifacts land." writeText(path, body), listKeys(dir), removeEntry(dir, name). Lives in packages/spec/src/file-writer.ts.
writeArtifactsTo The orchestrator. writeArtifactsTo(writer, agent, human, options?). Pure — validates with Zod, computes the file plan, delegates I/O to the writer. Lives in packages/emit/src/orchestrator.ts.
NodeFileWriter FileWriter backed by node:fs/promises. Auto-mkdirp on writeText, scoped to <root>/.facts/. Lives in packages/emit/src/node-writer.ts.
FsaFileWriter FileWriter backed by the File System Access API. Lives in packages/emit-browser/src/fsa-writer.ts. Carries a three-step macOS write-defense layer documented in §10.
writeArtifacts (Node shim) Thin top-level export from @factstack/emit. Constructs NodeFileWriter, calls the orchestrator, then runs ensureGitignoreEntry('.facts/'). ~20 LOC.
writeBrowserArtifacts (browser shim) Thin top-level export from @factstack/emit-browser. Constructs FsaFileWriter, calls the orchestrator. Backward-compatible surface for the in-browser scan flow.
Architectural principle

One adapter ⇒ hypothetical seam. Two adapters ⇒ real seam. Two FactsFS adapters (Node + memory) justified the read-tier seam. Two FileWriter adapters (Node + FSA) justified the write-tier seam. Adding a third costs ~50 LOC per adapter — no change to the orchestrator.

7 · Key flows

7.1 CLI analyze

$ factstack analyze /path/to/project
walker(NodeFS) → parsers → extractors → graph → scanners → intent → core
  → in-memory { agent: AgentArtifact, human: HumanArtifact }
  → writeArtifacts({ root, agent, human, writeSnapshot: true })
    → NodeFileWriter
    → writeArtifactsTo(writer, agent, human, { writeSnapshot: true })
    → ensureGitignoreEntry('.facts/')

The CLI is the canonical end-to-end path. Every tier is exercised. factstack ui additionally launches the local server (:4848) that powers the Remix UI's live re-analyze.

7.2 Browser scan

The Remix UI can scan a local directory entirely in the browser — no upload, no server. The flow:

  1. User clicks "Open" → showDirectoryPicker({ mode: 'read' }) → user grants read access.
  2. scanner.worker.ts (Web Worker) receives the directory handle, wraps it in FsaBrowserFS, runs the same isomorphic walker + parsers + extractors as the CLI.
  3. Worker posts { agent, human } back to main thread; scannerBridge.publishDataset hot-swaps the dashboard.
  4. User clicks "Save" → ensureWritePermission upgrades the handle to readwrite → writeBrowserArtifacts → FsaFileWriter → writeArtifactsTo → files land in <picked>/.facts/.

Same orchestrator runs in both the CLI and the browser. The browser path adds a permission-upgrade dance + the macOS write-defense layer detailed in §10.

7.3 MCP query

apps/mcp-server reads from .facts/ and exposes 5 tools to AI agents over MCP. Tools default to FactsPack response format for context efficiency (89% smaller than the equivalent agent.json slice). The facts://schema/{kind} resource exposes JSON Schemas so an agent can introspect the artifact shape before querying.

9 · Trust panel (OpenModal)

Recent feature in apps/ui-remix/src/components/OpenModal.tsx. The Open dialog surfaces a privacy disclaimer, a collapsible environment-check panel, and (after save) an inline file list + "Reveal in OS picker" affordance.

  • Disclaimer — plain-language reminder that everything stays on the device unless the user clicks Save. A refresh clears the in-memory analysis.
  • Permissions panel — collapsible. "All green" pill when every check passes; auto-expanded with red row + Grant button when any check fails. Checks: File System Access support, persistent storage, per-handle read perm, per-handle write perm.
  • View .facts files — inline list of files in .facts/ with sizes after save succeeds, plus a "Reveal in OS picker" button that calls showDirectoryPicker({ startIn: factsHandle }) — the closest a sandboxed browser can get to "open in Finder".

Probe logic extracted to apps/ui-remix/src/lib/envChecks.ts so it's testable in isolation. 18 unit tests cover every branch of computeEnvChecks.

10 · Recent significant changes

Write-tier deepening (commit d697226)

Eliminated ~200 LOC of duplicated orchestration between writeArtifacts and writeBrowserArtifacts. Introduced the FileWriter interface in spec/, the writeArtifactsTo orchestrator in emit/pure, and adapter classes in each tier. 15 of the 16 write-semantics tests moved to in-memory testing against MemoryFileWriter (9 ms vs 78 ms — 8.7× speedup).

macOS save-files fix

Users reported "save shows success but no files appear" on Macs. Root cause: three independent silent-failure modes in the File System Access path. FsaFileWriter.writeText now executes a three-step defense ritual:

  1. Write as Uint8Array, never raw string — WebKit pre-17 and some FSA polyfills silently produced 0-byte files on string input.
  2. Explicit truncate(byteLength) after write — defends against a real WebKit bug where close() resolved before the buffer flushed.
  3. Post-write readback verification — re-open via getFileHandle, compare file.size against expected. Mismatch throws an actionable error naming iCloud Drive, Documents/Downloads sandbox protection, and silently-denied write permission as the likely culprits.

Adapter-specific extras stay on the adapter side per the architectural principle in §4.3. The orchestrator and NodeFileWriter are untouched. Five regression-guard tests in packages/emit-browser/test/fsa-writer.test.ts cover every defense.

UI trust surface

See §9 for the full description. Added in May 2026 alongside the macOS fix.

Remix v3 modernization

Bumped remix@3.0.0-beta.0 → 3.0.0-beta.2. Switched all 45 source files from the standalone @remix-run/ui import to the canonical remix/ui subpath (the legacy standalone is on the way out). Migrated to the new RoutePattern.parse() + createHref() API from remix/route-pattern/href.

Astro support + Flow tab calibration

Added an Astro frontmatter extractor (slices the ----fenced block, parses as TypeScript via parseJS). Calibrated the Flow tab's tier classifier with Option B confidence-scored signals (filename suffix > directory segment > generic extension).

FactsPack bundle

v0.3.10 audit-driven bundle: FactsPack encoder, schema resource (facts://schema/{kind}), intent generator (packages/intent/), positive risks evidence, Overview health badge with one-click drill-through to /risks.

v0.6 — Security tier deepening (2026-05-27)

The Credentials + Vulnerabilities UI pages from v0.6.0 ran UI-only against live OSV.dev — the artifact carried no CVE data, so the MCP server couldn't serve it to agents and factstack analyze --json couldn't gate CI on it. The v0.6.1 deepening closes that gap end-to-end:

  • Schema: agent.dependencyManifests[] and agent.vulnerabilities[] added to packages/spec/src/agent.ts with .default([]) for backward compat. Per-finding shape includes severity, ecosystem, installed/fixed versions, advisory URL, manifest provenance, last-checked timestamp.
  • Dependency scanner (packages/scanners/src/dependencies.ts): detects 7 manifest types (package.json/pyproject.toml/Cargo.toml/go.mod/pom.xml/Gemfile/requirements.txt) in O(1) basename match. npm fully parsed (merges deps + devDeps + peer + optional); other ecosystems detected with empty deps (parser stubs, schema-ready). 18 unit tests cover the contract.
  • OSV client (packages/scanners/src/vulnerabilities.ts): shared two-stage protocol (batch IDs → per-vuln detail). Pluggable CacheStore — UI passes localStorageCache, CLI passes noopCache, tests pass an in-memory shim.
  • CLI: factstack scan-vulns [target] reads the artifact, flattens deps, queries OSV in batch, persists vulnerabilities[] via writeArtifacts. Opt-in (network required) so analyze stays C1-pure.
  • UI: Vulnerabilities page reads data.vulnerabilities first with a freshness chip; paste-driven OSV scan stays available below for one-off checks. Credentials page rule-reference now links to provider rotation docs per rule.
  • MCP: list_credentials + list_vulnerabilities tools in apps/mcp-server/src/server.ts with severity/ecosystem/package filters and a hint field when scan-vulns hasn't been run.

End-to-end demo: factstack analyze . && factstack scan-vulns . against this repo produces 21 manifests + 2 real high-severity GHSA findings on @modelcontextprotocol/sdk@1.0.0. Both findings show on factstack-demo.netlify.app/vulnerabilities.

12 · Build & deploy

pnpm install                                  # workspace install
pnpm -F @factstack/ui-remix build             # SPA + bundle-size check
pnpm -F @factstack/emit test                  # tests
pnpm -F @factstack/cli exec tsx src/cli.ts \
       analyze "D:/path/to/project"            # re-analyze the project

# Deploy
netlify deploy --filter @factstack/ui-remix \
       --dir=apps/ui-remix/dist --no-build --prod

The Netlify deploy serves apps/ui-remix/dist/ at factstack-demo.netlify.app. Static-file precedence means the /handoff/ and /design-handoff/ routes hit the docs first; everything else falls through to the SPA's catch-all at /index.html.

Bundle size enforcement lives in apps/ui-remix/scripts/check-bundle-size.mjs. Three caps: Main JS (72 KB gz), Lazy JS (200 KB gz), CSS (8 KB gz). Bumps require a justification comment in the script's history block.
